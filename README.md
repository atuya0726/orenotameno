# 俺のための過去問

情報処理安全確保支援士（SC）の学習アプリです。選択肢を押すと、そのまま「自信あり」で回答します。迷ったときは先に「迷いあり」をオンにします。答えを選べないときは「わからない」で解説へ進めます。

## 起動

Node.js 24以上を使用してください。

```sh
npm install
npm run dev
```

表示されたローカルURL（通常は http://127.0.0.1:5173 ）をブラウザで開きます。

## 試せること

- 学習ホームの「問題を選ぶ」で、過去問道場のように出題範囲を指定して演習（試験回を指定・分野を指定・模擬試験の3方式。分野指定は試験回でも絞り込める。出題対象は すべて・未学習・要復習・あとで見る、計算問題は 含める・出題しない・のみ、出題順は ランダム・試験回と番号順、出題数も選択。設定はブラウザに記憶）
- 問題一覧での検索、未学習・あとで見るによる絞り込み
- 選択肢を1回押して即採点（通常は自信あり。迷ったときは先に「迷いあり」をオン）
- 「わからない」は答えを選ばず、未解答として記録して解説へ進む
- 知識問題・計算問題ともに、答えと回答時の自信を記録
- 採点、選択肢ごとの解説、回答時の自信・迷いの振り返り
- KaTeXによる数式表示（分数・添字・論理式の上線、文中と独立した式）
- 正誤・迷い・復習希望に応じて復習の重さを記録し、重い問題から再演習
- 回答履歴、確信度別の正答率、日々の目標
- IndexedDBへの保存、途中入力の復元、JSONバックアップの書き出し・統合

収録内容は**令和5年度春期〜令和7年度秋期の高度試験／情報処理安全確保支援士試験の午前Ⅰ（科目A1相当）6回分 全180問**と、**令和7年度春期・秋期の情報処理安全確保支援士試験の午前Ⅱ（科目A2相当）2回分 全50問**です。令和7年度秋期は2026年10月20日のIPA公開一覧で確認できた最新公開分です。試作用オリジナル問題は削除しました。収録の詳細は `docs/sources/` にあります。

問題はIPAの公表問題に基づき、正答は[公式解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07a_koudo_am1_ans.pdf)と照合しています。空白・句読点・数式を表示用に整え、図はSVG、表はHTML、SQL文は等幅のコード表示に再構成しました（回ごとの変更点は `docs/sources/` を参照）。各選択肢の解説は当サイト独自のものです。各問に出典、表記変更の説明、公式問題PDFへのリンクを付けています。A2も同じ方針で、正答は[秋期の公式解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07a_sc_am2_ans.pdf)と[春期の公式解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07h_sc_am2_ans.pdf)と照合しています。秋期問22の図をSVG、秋期問24と春期問21の表をHTMLに再構成し、春期問21のSQL文は等幅表示にしています。

過去問の追加手順は `.agents/skills/add-past-exam/SKILL.md`（Claude Code・Codex共通のスキル）にまとめています。`scripts/past-exam/fetch.sh <試験> <西暦> <autumn|spring> <am1|am2>` で公式PDFの取得・正答の抽出・ページ画像の作成・データの雛形作成までを自動で行います。

ローカルURLは http://127.0.0.1:5173/ 、A1の演習は http://127.0.0.1:5173/study/A1 です。`npm run dev` を実行している間に開けます。公開済みURLはまだありません。

## 復習ルール

選択肢を押すと回答し、解説を読んでから「復習リストに追加」を付け外しできます。回答前の自信の入力はありません。「わからない」は未解答として記録します。以前の「迷った」は「復習リストに追加」の選択状態に引き継ぎ、このボタンで解除できます。以前の自信や「これも迷った」はデータとして保持します。

復習の重さは、各問題の直近の回答で更新します。

| 回答の状態 | 復習の重さ |
| --- | --- |
| わからない、または不正解 | 3（優先して復習） |
| 正解だが「復習リストに追加」がオン、または復習する単語を選択 | 2（要復習） |
| 自信ありで正解し、復習希望なし | 0（対象外） |

解説下の「復習したい単語を選択」から、意味が曖昧だった単語を複数選べます。候補は各問題の本文・選択肢・図表・解説から用意し、単語は共通リストとしてIndexedDBとバックアップに保存します。同じ単語は別の問題でも選択済みになり、正解でも復習対象に入ります。復習ノートの「単語を復習」を押すと、登録した単語をランダムな順に1語ずつ用語学習で説明できます。単語の一覧と登録解除は、用語学習の「復習する単語」フィルタで行います。解除すると全問題の選択状態を更新しますが、問題自体の「復習リストに追加」がオンなら復習対象に残ります。

わからない・不正解の問題は、ボタンや単語の選択にかかわらず重さ3です。復習対象だった問題も、自信ありで正解して復習希望も選択単語もなければ、キューから外れます。以前の記録の正解で自信が低・中の場合は重さ2として扱います。重い問題から先に並び、待ち時間なしで復習できます。

計算問題（例：令和7年度秋期A1の問1・3・10・19・29）は各回のデータで明示しています。知識問題と同じ操作で回答できます。

以前の時間方式・回数方式の記録も、回答履歴から重さを再計算します。自信ありの正解を復習対象に残しません。回答と復習状態の保存、途中入力の削除は一つのIndexedDBトランザクションで実行します。

## 用語トレーニング

`/glossary` に過去問とは別の学習システムを追加しました。署名、ハッシュ、TLS、SQLインジェクション、XSS、CSRF、MFA、DNS、SPF、DKIM、ACIDに加え、科目A2で出題されたPKI、PQC、Pass the Hash、ドメインフロンティング、UEBA、CSPM、IEEE 802.1Xなどを収録しています。過去問の復習単語の候補はすべて、名前か別名（`aliases`）でいずれかの用語に対応させています（`src/data/question-terms.test.ts` で検査）。

1. 用語を選ぶ。説明例を先に読むことも、自分の理解だけで説明することもできます。
2. 日本語の音声か文字で説明する。音声は停止後に聞き間違いを修正できます。
3. 「AIに説明をチェックしてもらう」で、説明できた要点・事実上の誤り・不足する内容・改善した説明例を確認する。
4. もう一度説明する、次の用語に進む、履歴で過去の説明を見返す。

評価はキーワード照合ではなくLLMが文脈や否定を読んで行います。用語の定義と評価項目はサーバー側のデータを使い、構造化された返答をZodで検証します。項目の欠落・重複や、説明原文に存在しない引用は評価結果として保存しません。AIには誤りがあり得るため、説明例も合わせて表示します。

### 評価の段階（S / A / B / C）

各用語の要点は、難しさではなく**試験での出題頻度**で3段階に分けています。

| 段階 | 名前 | 基準 |
|---|---|---|
| B | 基本 | 試験で繰り返し問われる性質・論点。最低限ここまでは説明したい |
| A | 応用 | 試験でときどき問われる論点 |
| S | 発展 | 試験ではめったに問われないが、知っていると理解の深さが光る論点 |

原則1用語につき1概念とし、その説明に必要な要点だけを扱います。Bが1個だけでもよく、A・Sは必要な場合だけ設けます。サーバー証明書とクライアント証明書、クラッシングとファストトラッキングなどはそれぞれ独立した用語です。編集時の判断基準は[用語学習の編集方針](docs/glossary-authoring.md)にまとめています。

判定は実際にある段階だけを下から積み上げます。Bの要点がすべて言えていればB、さらにAもすべて言えていればA、Sまで言えていればSです。Bだけの用語は全項目を説明できてもBで、存在しないA・Sは要求しません。Bに足りない要点があるか、どの段階でも内容に誤りがあればCになります。要点の定義は `src/features/glossary/terms.ts`（`level` がないものはB）、段階の文言は `src/features/glossary/model.ts` の `levelInfo` にあり、AIへの指示と画面の両方がそこを参照します。

評価ボタンを押したときだけ1回APIを呼びます。自動採点・自動再試行・ツール呼び出しは行わず、最大出力3,000トークンに制限します。モデルは `OPENAI_MODEL` で変更できます。キー未設定・接続失敗時はその旨を表示し、架空の評価を返しません。

収録済みの用語では、AIの出力を評価項目IDごとの必須キーを持つ構造に固定し、項目の欠落・重複を防ぎます。エラー時は画面に確認番号を表示し、Cloudflare Workers Logsで同じ番号の `glossary_evaluation_failed` を検索できます。コードは `AI_TIMEOUT`（時間切れ）、`AI_RATE_LIMITED`（混雑・利用上限）、`AI_OUTPUT_LIMIT`（出力上限）、`AI_EVIDENCE_INVALID`（引用不一致）、`AI_CRITERIA_INVALID`（項目不整合）などです。ログに残すのは確認番号・コード・HTTP状態（取得できた場合はOpenAI側の状態も含む）・収録用語ID・所要時間だけで、説明文・任意に入力した用語名・APIキー・AIの返答本文は記録しません。通常のリクエストログは無効にしています。

### ローカルでOpenAIに接続

`.env.example` を `.env.local` にコピーし、`OPENAI_API_KEY` を設定してから `npm run dev` を起動します。キーを `VITE_` で始める変数に入れないでください。Viteのサーバー用ミドルウェアと本番Workerが同じAPIハンドラーを使います。キーはクライアントコード・IndexedDBには保存しません。

```sh
cp .env.example .env.local
# .env.local の OPENAI_API_KEY を設定
npm run dev
```

URL: http://127.0.0.1:5173/glossary （開発サーバー実行中に利用できます）。この作成環境にはOpenAI APIキーがないため、実際のLunaによる評価は未検証です。APIと画面のテストには明示的なモックを使用し、実サービスはモックで代替しません。

音声入力は対応ブラウザとマイクの許可が必要です。使えない環境では文字入力できます。音声認識サービスへの音声送信が発生する場合があります。AI評価時には現在の説明文と対象用語の資料をOpenAIへ送信します。過去の学習履歴や音声そのものはLLMへ送信しません。Responses APIには `store: false` を指定しています。

下書き・説明文・評価・モデル名・説明例を参照したかどうかは、過去問とは別のIndexedDB `orenotameno-glossary` に保存します。バックアップは用語学習の「説明の履歴」から書き出し・取り込みができます。過去問の設定画面のバックアップには含まれません。

## データの扱い

記録は同じブラウザ・同じオリジン内だけで共有されます。端末、ブラウザ、URLのホスト名やポートを変えると別の保存領域になります。ブラウザのデータ消去に備えて設定画面からJSONを書き出せます。取り込みは既存の記録と統合し、同じ回答IDを重複登録しません。不正な形式のファイルは書き込み前に拒否します。書き出し形式はバージョン4で、以前のバージョン1〜3のバックアップも取り込めます。復習する単語は重複を除いて統合し、旧形式では回答に保存された選択単語を共通リストへ引き継ぎます。復習状態は統合した回答履歴から再計算し、古い予定で完了済みの問題が復活しないようにします。旧方式の途中入力は、選択中の答えと、迷いに相当する選択肢を引き継ぎます。

## Cloudflare Workersへの配置

```sh
npx wrangler login
npx wrangler secret put OPENAI_API_KEY
npm run deploy
```

`src/worker.ts` と `dist` をCloudflare Workersへ配置します。`/api/*` はWorkerを優先し、それ以外はStatic AssetsでSPAを表示します。D1は不要です。AI評価にはOpenAI APIキーのシークレット設定が必要です。Wranglerでローカル確認する場合は `.dev.vars.example` を `.dev.vars` にコピーしてキーを設定し、本番ビルド後に `npx wrangler dev` を使います。静的ファイルだけを配信するホストではAI評価APIは動きません。
