# 俺のための過去問

情報処理安全確保支援士（SC）の学習アプリです。選択肢を押すと、そのまま「自信あり」で回答します。迷ったときは先に「迷いあり」をオンにします。答えを選べないときは「わからない」で解説へ進めます。

## 起動

Node.js 24以上を使用してください。

```sh
npm install
npm run dev
```

表示されたローカルURL（通常は http://127.0.0.1:5173 ）をブラウザで開きます。

## 試せること

- 学習ホームの「問題を選ぶ」で、過去問道場のように出題範囲を指定して演習（試験回を指定・分野を指定・模擬試験の3方式。分野指定は試験回でも絞り込める。出題対象は すべて・未学習・要復習・あとで見る、計算問題は 含める・出題しない・のみ、出題順は ランダム・試験回と番号順、出題数も選択。設定はブラウザに記憶）
- 問題一覧での検索、未学習・あとで見るによる絞り込み
- 選択肢を1回押して即採点（通常は自信あり。迷ったときは先に「迷いあり」をオン）
- 「わからない」は答えを選ばず、未解答として記録して解説へ進む
- 知識問題・計算問題ともに、答えと回答時の自信を記録
- 採点、選択肢ごとの解説、回答時の自信・迷いの振り返り
- KaTeXによる数式表示（分数・添字・論理式の上線、文中と独立した式）
- 正誤・迷い・復習希望に応じて復習の重さを記録し、重い問題から再演習
- 回答履歴、確信度別の正答率
- 学習履歴のIndexedDBへの自動保存、sessionStorageからの途中入力の復元
- 模擬試験・演習の進行状況はsessionStorageに一時保存し、同じタブでのリロード後も出題順・現在の問題・回答結果・解説を復元。ホームの「続きから再開」も同じタブ内で利用でき、「出題開始」「もう一度解く」では新しく開始。タブを閉じた後の新しいタブには進行状況を引き継がない
- 回答前の選択肢の印・途中入力、用語説明の下書き、電卓の入力と計算履歴もsessionStorageに一時保存。以前IndexedDBやlocalStorageに保存した作業用データは起動時に削除

収録内容は**令和5年度春期〜令和7年度秋期の高度試験／情報処理安全確保支援士試験の午前Ⅰ（科目A1相当）6回分 全180問**と、**令和4〜7年度春期・秋期の情報処理安全確保支援士試験の午前Ⅱ（科目A2相当）8回分 全200問**です。令和7年度秋期は2026年10月20日のIPA公開一覧で確認できた最新公開分です。試作用オリジナル問題は削除しました。収録の詳細は `docs/sources/` にあります。

問題はIPAの公表問題に基づき、正答は[公式解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07a_koudo_am1_ans.pdf)と照合しています。空白・句読点・数式を表示用に整え、図はSVG、表はHTML、SQL文は等幅のコード表示に再構成しました（回ごとの変更点は `docs/sources/` を参照）。各選択肢の解説は当サイト独自のものです。各問に出典、表記変更の説明、公式問題PDFへのリンクを付けています。A2も同じ方針で、正答は[秋期の公式解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07a_sc_am2_ans.pdf)と[春期の公式解答例](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07h_sc_am2_ans.pdf)と照合しています。令和7年度秋期の階層図に加え、令和6年度春期の課金グラフ、令和5年度秋期のネットワーク構成図、令和4年度秋期の流れ図もSVGで再作成しています。SQL・投資案・責務分担などの表はHTML、SQL文とHTTPヘッダは等幅表示にしています。

過去問の追加手順は `.agents/skills/add-past-exam/SKILL.md`（Claude Code・Codex共通のスキル）にまとめています。`scripts/past-exam/fetch.sh <試験> <西暦> <autumn|spring> <am1|am2>` で公式PDFの取得・正答の抽出・ページ画像の作成・データの雛形作成までを自動で行います。

ローカルURLは http://127.0.0.1:5173/ 、A1の演習は http://127.0.0.1:5173/study/A1 です。`npm run dev` を実行している間に開けます。公開済みURLはまだありません。

## 復習ルール

選択肢を押すと回答し、解説を読んでから「復習リストに追加」を付け外しできます。回答前の自信の入力はありません。「わからない」は未解答として記録します。以前の「迷った」は「復習リストに追加」の選択状態に引き継ぎ、このボタンで解除できます。以前の自信や「これも迷った」はデータとして保持します。

復習の重さは、各問題の直近の回答で更新します。

| 回答の状態 | 復習の重さ |
| --- | --- |
| わからない、または不正解 | 3（優先して復習） |
| 正解だが「復習リストに追加」がオン、または復習する単語を選択 | 2（要復習） |
| 自信ありで正解し、復習希望なし | 0（対象外） |

解説下の「復習したい単語を選択」から、意味が曖昧だった単語を複数選べます。候補は各問題の本文・選択肢・図表・解説から用意し、単語は共通リストとしてIndexedDBに保存します。同じ単語は別の問題でも選択済みになり、正解でも復習対象に入ります。復習ノートの「単語を復習」を押すと、登録した単語をランダムな順に1語ずつ用語学習で説明できます。単語の一覧と登録解除は、用語学習の「復習する単語」フィルタで行います。解除すると全問題の選択状態を更新しますが、問題自体の「復習リストに追加」がオンなら復習対象に残ります。

わからない・不正解の問題は、ボタンや単語の選択にかかわらず重さ3です。復習対象だった問題も、自信ありで正解して復習希望も選択単語もなければ、キューから外れます。以前の記録の正解で自信が低・中の場合は重さ2として扱います。重い問題から先に並び、待ち時間なしで復習できます。

計算問題（例：令和7年度秋期A1の問1・3・10・19・29）は各回のデータで明示しています。知識問題と同じ操作で回答できます。

以前の時間方式・回数方式の記録も、回答履歴から重さを再計算します。自信ありの正解を復習対象に残しません。回答と復習状態は一つのIndexedDBトランザクションで保存し、成功後にsessionStorageの途中入力を削除します。

## 用語トレーニング

`/glossary` に過去問とは別の学習システムを追加しました。署名、ハッシュ、TLS、SQLインジェクション、XSS、CSRF、MFA、DNS、SPF、DKIM、ACIDに加え、科目A2で出題されたPKI、PQC、Pass the Hash、ドメインフロンティング、UEBA、CSPM、IEEE 802.1Xなどを収録しています。過去問の復習単語の候補はすべて、名前か別名（`aliases`）でいずれかの用語に対応させています（`src/data/question-terms.test.ts` で検査）。

1. 用語を選ぶ。説明例を先に読むことも、自分の理解だけで説明することもできます。
2. 日本語の音声か文字で説明する。音声は停止後に聞き間違いを修正できます。
3. 「AIでチェック」で、各評価項目のチェックアイコンを確認する。説明できた項目・未説明の項目・誤りがある項目を区別します。
4. もう一度説明する、次の用語に進む、履歴で過去の説明を見返す。

評価はキーワード照合ではなくLLMが文脈や否定を読んで行います。収録済みの用語だけを対象に、サーバー側の定義と評価項目を使います。Decisions APIに項目ごとの3択（説明できた・未説明・誤り）をまとめて送り、返答をZodで検証します。項目の欠落・重複・未知のIDや拒否を含む返答は保存しません。引用・総評・文章のフィードバック・次の用語の提案は生成せず、不足や誤りのある評価項目をアイコンで示します。用語の説明例は収録データから表示します。

説明文にない情報を参照資料や一般知識で補わず、項目に必要な意味全体を確認します。正しい言い換えに加え、入力方法を問わず誤字・脱字・近い音の誤変換・助詞の誤りを前後の語と動作から自然に読み取ってから採点し、明確な言い直しは訂正後を評価します。文末が途切れていても意味が伝わった項目は認め、他の項目の未説明を理由に取り消しません。表記だけで不足・誤りにせず、公開鍵と秘密鍵などの概念の取り違えは内容の誤りとして扱います。「説明できた」の選択に加えて、その推定確率が70%以上であることを合格条件にしています。下限未満は時計のアイコンと「判定保留」で示し、合格項目には数えません。元の選択・3択の確率・別指標のconfidence・適用した下限を履歴とバックアップに残します。確率の欠落や不正な分布を含む返答は採用しません。70%は調整可能な暫定基準で、正答率の保証ではありません。下限は `src/server/glossary-evaluator.ts` の `MIN_COVERED_PROBABILITY` で管理し、保存済みの評価は書き換えません。

誤字を含む説明と表記を直した説明の実API比較は、[誤字・脱字の評価確認](docs/glossary-evaluation-checks.md)にまとめています。

### 評価の段階（S / A / B / C）

各用語の要点は、**試験で必要な理解の深さ**で3段階に分けています。

| 段階 | 名前 | 基準 |
|---|---|---|
| B | 基本 | 用語の意味・目的・基本の仕組み |
| A | 応用 | 基本を踏まえた用途・理由・制約・影響 |
| S | 発展 | 試験範囲内の細かな条件・仕様・例外 |

原則1用語につき1概念とし、その説明に必要な要点だけを扱います。Bが1個だけでもよく、A・Sは必要な場合だけ設けます。出題頻度は学習順の参考情報として扱います。サーバー証明書とクライアント証明書、クラッシングとファストトラッキングなどはそれぞれ独立した用語です。編集時の判断基準は[用語学習の編集方針](docs/glossary-authoring.md)と[用語評価の基準](docs/glossary-rubric.md)にまとめています。

判定は実際にある段階だけを下から積み上げます。Bの要点がすべて言えていればB、さらにAもすべて言えていればA、Sまで言えていればSです。Bだけの用語は全項目を説明できてもBで、存在しないA・Sは要求しません。Bに足りない要点があるか、どの段階でも内容に誤りがあればCになります。要点の定義は `src/features/glossary/terms.ts`（`level` がないものはB）、段階の文言は `src/features/glossary/model.ts` の `levelInfo` にあり、結果画面と復習目標の選択画面が参照します。

評価ボタンを押したときだけ1回APIを呼びます。共通の採点方針は共有入力に1回だけ含め、各項目には短い指示を付けます。全項目を1回のリクエストで判定し、自動採点・自動再試行・文章生成・ツール呼び出しは行いません。Decisions APIに対応する `gpt-6-luna` を使います。`OPENAI_MODEL` に未対応モデルを設定すると、APIを呼ぶ前に設定エラーを返します。キー未設定・接続失敗時はその旨を表示し、架空の評価を返しません。[APIの公式仕様](https://developers.openai.com/api/docs/guides/decisions)に沿って `choice` を使用しています。

返答の項目IDを収録データと照合し、順序が異なっても元の項目へ対応させます。エラー時は画面に確認番号を表示し、Cloudflare Workers Logsで同じ番号の `glossary_evaluation_failed` を検索できます。コードは `AI_TIMEOUT`（時間切れ）、`AI_RATE_LIMITED`（混雑・利用上限）、`AI_REFUSED`（判定の拒否）、`AI_RESPONSE_INVALID`（形式不正）、`AI_CRITERIA_INVALID`（項目不整合）などです。ログに残すのは確認番号・コード・HTTP状態（取得できた場合はOpenAI側の状態も含む）・収録用語ID・所要時間だけで、説明文・APIキー・AIの返答本文は記録しません。通常のリクエストログは無効にしています。

### ローカルでOpenAIに接続

`.env.example` を `.env.local` にコピーし、`OPENAI_API_KEY` を設定してから `npm run dev` を起動します。キーを `VITE_` で始める変数に入れないでください。Viteのサーバー用ミドルウェアと本番Workerが同じAPIハンドラーを使います。キーはクライアントコード・IndexedDBには保存しません。

```sh
cp .env.example .env.local
# .env.local の OPENAI_API_KEY を設定
npm run dev
```

URL: http://127.0.0.1:5173/glossary （開発サーバー実行中に利用できます）。この作成環境にはOpenAI APIキーがないため、実際のLunaによる評価は未検証です。APIと画面のテストには明示的なモックを使用し、実サービスはモックで代替しません。

音声入力は対応ブラウザとマイクの許可が必要です。使えない環境では文字入力できます。音声認識サービスへの音声送信が発生する場合があります。AI評価時には現在の説明文・音声入力を使ったかどうか・対象用語の資料をOpenAIへ送信します。音声入力の場合は音声認識の書き起こしであることを明示し、同音の漢字違いだけでなく、読みの音が近い語も前後の意味から読み取るよう指示します。ユーザーが意図を明示した誤認識は、該当する用語の採点入力だけで復元します（例：ROC曲線の「利用成立」→「偽陽性率」）。入力文と履歴の原文は書き換えません。過去の学習履歴や音声そのものはLLMへ送信しません。未収録の用語に対して生成APIを呼ぶ処理はありません。

評価済みの説明文・評価・モデル名・説明例を参照したかどうかは、過去問とは別のIndexedDB `orenotameno-glossary` に保存します。下書きはsessionStorageに保存します。バックアップは用語学習の「説明の履歴」から書き出し・取り込みができ、評価済みの記録だけを書き出します。以前のバックアップに含まれる下書きは現在のタブに一時復元します。

判定が返った時点で結果を表示し、履歴は裏で保存します。保存のたびに全履歴を読み直さず、画面上の今回の記録と下書きだけを更新します。保存失敗時も結果と下書きを画面内に保持し、「保存を再試行」で追加のAI呼び出しなしに保存できます。未保存の結果は用語学習内の履歴でも再試行でき、復習キューからの解除は評価の保存に成功してから行います。

## データの扱い

学習履歴は同じブラウザ・同じオリジン内で共有され、一時データはタブごとに保存されます。端末、ブラウザ、URLのホスト名やポートを変えると別の保存領域になります。回答履歴・復習状態・復習する単語・ブックマークは自動保存します。設定・データ管理画面と過去問の記録を書き出し・取り込みする操作は削除しました。用語学習の履歴のバックアップは引き続き利用できます。
