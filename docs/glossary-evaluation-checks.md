# 誤字・脱字の評価確認

単体テストのモック応答では、採点指示が実際のモデルに伝わったか確認できない。誤字を含む説明と、表記だけ直した説明を実APIで比較する。

## 修正前に確認した結果（2026-10-21）

Pass the Hash攻撃で、稼働中のAPIへ各1回送信した結果。実行先は `https://orenotameno.atuya07261008-748.workers.dev`。当時は採点方針のバージョンを返していなかったため、適用されたコミットは特定できない。

| 入力 | `hash-auth` の選択 | coveredの推定確率 | 期待 |
|---|---|---|---|
| パスワードのハッシュ時だけをみて認証する仕組みは悪用して | missing | 38% | covered |
| パスワードのハッシュ値だけをみて認証する仕組みを悪用して | missing | 49% | covered |

両方とも「ハッシュ値だけで認証できる仕組みを悪用する」という論点は伝わる。「解読せず、そのまま認証に使う」はこの文では説明されていないため、そちらの項目はmissingのままにする。したがって、この入力だけで最終評価がCになること自体は変更対象ではない。

## 実APIによる確認

[確認例](../scripts/glossary/typo-cases.json)は、上の2文、基本項目を説明した誤字あり・修正済みの2文、事実の誤り、未説明の計6件。項目別の最終statusを確認し、推定確率も出力する。モデルの揺らぎがあるため、1回の成功は常に同じ結果になる保証ではない。

明示的に実行した場合だけ6回の有料AI評価を行う。通常の `npm test` には含めず、自動再試行しない。

```sh
node scripts/glossary/check-typo-tolerance.mjs https://対象サイト 2026-10-21-typo-fragments
```

最初にGETで `X-Glossary-Policy` を確認し、指定した採点方針と異なる場合はAI評価を送信せず終了する。これにより、旧版のAPIを新しい指示の検証結果として扱うことを避ける。
